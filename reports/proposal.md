## 3. 设计方案

**修改模块：**

- rCore 设备驱动与设备初始化：增加 QPU 设备、MMIO 映射及平台配置。
- 系统调用与用户库：增加提交、查询、等待及结果回收接口。
- 任务管理与同步：维护设备任务、所有权、等待队列和退出清理。
- 外部中断处理：连接设备 IRQ、读取完成状态并触发唤醒。
- 新增设备调度模块：在同一队列框架中切换 FCFS、SJF、SJF+aging。
- QEMU 与 FPGA：分别实现虚拟设备模型和 RTL 外设，保持协议一致。

**核心机制：**

用户进程通过内核接口提交 Job，内核复制并检查描述符，分配任务句柄并加入有界队列。设备调度器仅在设备空闲时选择下一任务；CPU 进程调度仍沿用 rCore 的机制。CPU 调度决定哪个进程使用 CPU，设备调度决定哪个任务使用 QPU；设备任务不采用 CPU 时间片。本阶段采用单设备、单执行槽、任务独占且不可抢占的模型，不实现 DMA、多任务并行、跨任务量子态保持或设备分区。

交互路径为：用户程序 → 系统调用 → 内核 Job 队列与设备调度器 → 驱动 → MMIO → QPU Emulator；完成路径为：设备结果与 IRQ → 中断处理 → Job 完成及唤醒 → 用户结果回收。

**任务模型与资源约束：**

| 字段 | 含义与使用方式 |
| --- | --- |
| job_id、owner | 内核生成的任务标识和所属进程，不信任用户自报身份 |
| circuit_tag、seed | 抽象线路标签和结果种子，仅用于一致性校验 |
| n_qubits、depth、shots | 资源规模元数据；检查上限，不据此执行量子算法 |
| estimated_ticks | 供调度器使用的预计服务时长，必须为正且有上限 |
| actual_ticks | 设备模型的实际延迟，由可信测试配置提供给驱动或设备后端，仅用于模拟执行，不参与调度选择 |
| arrival_seq、timestamps | 内核接收顺序，以及入队、派发、完成和回收时间 |
| state、result、error | 生命周期、确定性测试结果及失败原因 |

基准负载可用“固定准备成本 + depth × shots × 每层成本”生成 actual_ticks，也可从预定义轨迹导入。这些系数仅用于构造测试负载，不表示真实 QPU 的执行成本。驱动在派发时将 actual_ticks 换算为设备周期数并写入 EXEC_TICKS；调度函数只接收 estimated_ticks、到达顺序和等待时间，不使用 actual_ticks 排序。这是实验中的信息使用约束，不是内核内部的安全隔离。

n_qubits 只作容量合法性约束；合法任务均独占整台模拟设备，不实现量子比特空间共享。估时准确组令 estimated_ticks 等于 actual_ticks；误差组单独扰动 estimated_ticks，保留真实服务时长不变，分别观察理想估时和估时不准时的结果。

正常情况下，内核 Job 依次经历 QUEUED → RUNNING → COMPLETED/FAILED → REAPED；排队期间被清理或因设备不可用而终止的任务，则从 QUEUED 转为 FAILED 后回收。排队任务可在进程退出时清理；运行任务不强行抢占，完成后丢弃无人接收的结果并回收资源。任务句柄绑定进程并带代际信息，防止复用导致错误匹配。全局等待队列、Job 对象总数和每进程未回收任务数均设置上限；已完成但尚未回收的结果仍占用额度，防止用户不取结果造成内存持续增长。达到相应上限时，提交接口返回明确的资源不足错误。非法地址、参数溢出、无权访问和重复回收均返回错误。

**关键流程：**

1. qpu_submit(desc) 验证参数并复制用户数据，成功入队后立即返回句柄；用户进程无需在任务排队期间忙等。
2. 设备空闲时，在队列锁保护下选择任务并标记 RUNNING，驱动写入参数，最后写 START；使用 volatile 访问及平台要求的内存屏障保证顺序。
3. FPGA 或 QEMU 设备锁存参数，进入 BUSY，等待配置的执行延迟，产生确定性结果并进入 DONE 或 ERROR。
4. 设备保持完成状态和电平中断，直至驱动确认。中断处理读取 job_id、状态和结果，核对当前任务，更新内核状态，清除设备中断并完成中断控制器应答，再唤醒等待者并启动后续调度。
5. qpu_query(handle) 无阻塞查询；qpu_wait(handle) 在同一同步保护下检查完成条件并登记等待者，再安全阻塞。完成先于 wait 时立即返回，避免“检查后完成、尚未睡眠”造成丢失唤醒。
6. qpu_get_result(handle) 将完成结果复制给所属进程，成功回收后释放句柄；用户复制失败时保留可重试结果。等待和结果回收分离，用户可在提交后继续 CPU 工作。
7. 超时由内核定时检查触发，将当前任务标记失败并复位设备；复位后先清除设备和中断控制器中的残留状态，再恢复派发；JOB_ID 在有效任务及迟到事件可能存在期间不复用，并结合内核代际信息拒绝过期结果。复位失败则将设备标为不可用，并使待处理请求显式失败。

**FPGA 设备抽象：**

拟采用 32 位寄存器、4 字节对齐访问和单任务锁存接口，寄存器偏移为协议设计值；MMIO 基地址、IRQ 编号、总线类型和设备时钟均待平台确定后填写。软件队列位于 OS，FPGA 只保留一个在执行任务，避免硬件排队掩盖 OS 调度决策。

| 偏移 | 寄存器 | 约定 |
| --- | --- | --- |
| 0x00 | VERSION | 只读协议版本 |
| 0x04 | STATUS | IDLE、BUSY、DONE、ERROR |
| 0x08 | CONTROL | START、ACK、RESET 命令 |
| 0x0C | JOB_ID | 启动时锁存，完成时保持 |
| 0x10 | EXEC_TICKS | 模型执行延迟，正整数 |
| 0x14 | SEED | 确定性结果生成参数 |
| 0x18 | RESULT | 如 SEED 与 JOB_ID 的异或值，不是量子测量结果 |
| 0x1C | IRQ_STATUS | 完成或错误中断挂起状态 |
| 0x20 | ERROR_CODE | 错误原因 |
| 0x24 | IRQ_ENABLE | 中断使能 |
| 0x28 | BUSY_CYCLES_LO | 累计 BUSY 周期计数的低 32 位 |
| 0x2C | BUSY_CYCLES_HI | 累计 BUSY 周期计数的高 32 位 |

RTL 由寄存器接口、命令译码、状态机、延迟计数器、结果逻辑和 IRQ 逻辑组成。START 仅在 IDLE 接受；BUSY 期间重复 START 不覆盖运行任务，并记录协议错误。DONE/ERROR 的结果保持到 ACK；ACK 后回到 IDLE。RESET 清除执行状态及挂起中断。软件等待者不直接操作寄存器。BUSY 期间的错误命令只记录协议错误，不将正在运行的任务改为 ERROR，也不提前发出完成中断；运行任务自身失败时才进入 ERROR。

BUSY 周期累计计数器独立于任务状态，任务 ACK 和普通设备 RESET 不清零；由平台复位清零。驱动用“高位—低位—高位”读法检查溢出并重试，在测量窗口边界读取差值。QEMU 提供语义相同的计数器，按已配置的虚拟设备频率换算周期。

QEMU 使用虚拟时间定时器产生完成事件，通过虚拟中断控制器送达 rCore；FPGA 使用设备时钟计数器。两者采用相同的接口和状态语义，但宿主机时间、QEMU 虚拟时间与 FPGA 周期需分别计量。硬件优先采用运行 rCore 的 RISC-V CPU 与 FPGA 内存映射外设直连方案；CPU 来源、地址空间和中断路径为平台选型阶段的必验条件。QEMU 的普通 MMIO 读写不会自动连接外接 FPGA。

**调度策略：**

- FCFS：从已到达且合法的任务中选 arrival_seq 最小者。
- SJF：从就绪队列中选 estimated_ticks 最小者；相同时按 arrival_seq 排序，作为消融对照。
- SJF+aging：若存在等待时间达到阈值 A 的任务，优先选择其中 arrival_seq 最小者；否则执行 SJF。A 是时间阈值，以同一时钟单位表示，属于策略配置，不是性能目标。每次设备空闲时重新判断，不中断已运行任务。

阈值式 aging 的规则明确：任务等待达到 A 后，按到达顺序优先执行。在服务时长有限、队列有限且设备正常推进的前提下，后来到达的短任务不会无限插队；但它不保证任意过载或故障场景下的固定完成时限。A 越小越接近 FCFS，越大越接近 SJF。初始拟比较 A 为参考服务时长 s0 的 5、20、100 倍，完整报告各组结果。若需选择一个默认阈值，应使用单独的校准负载确定，再在正式实验中固定，避免只展示最有利的参数。

**技术难点：**

主要难点是任务提交与完成之间的竞态、中断上下文中的同步、进程退出后的资源回收，以及 QEMU 与 FPGA 的协议一致性。实现时固定锁顺序，不在阻塞时持有设备锁，缩短中断处理路径，使用事件日志核对状态转换。调度复杂度先采用有界队列线性扫描，记录每次选择的耗时和队列长度，待数据证明必要后再优化数据结构。

风险还包括候选基线工具链失配、QEMU 设备开发成本以及 FPGA 平台不能直接运行 rCore。首阶段优先复现基线并确认硬件拓扑，保留 QEMU 完整实现作为可独立复现的软件成果。若上板失败，仍交付 RTL 仿真结果和故障分析，并将硬件端到端验收标记为未完成。

## 4. 分类要求

### 4.1 科研型

#### 4.1.1 研究问题与假设

RQ1：在单设备、不可抢占的 QPU 任务行为模型中，按预计执行时长选择任务，在哪些负载下能比 FCFS 减少等待和周转时间？

H1：当长短任务混合、队列中同时存在多个可选任务且估时较准确时，SJF 类策略可能降低平均等待和周转时间；同长度、低负载或长任务已经开始执行时，收益可能很小或不存在。通过不同负载和估时误差分组检验该假设。

RQ2：加入 aging 后，长任务的尾部等待时间与短任务的平均延迟如何变化？

H2：持续短任务到达时，阈值式 aging 相对纯 SJF 可能减少长任务最大等待和未完成比例，但可能增加短任务延迟；其效果取决于阈值和负载。实验将同时报告这两方面的变化。

RQ3：从 QEMU 虚拟设备迁移到 FPGA 外设时，相同任务协议能否保持端到端正确性，设备访问和中断开销是否改变调度效果？

H3：在共享协议下，两后端应产生一致的合法状态转换和结果。对于很短的任务，提交、中断与调度开销可能占较大比例，使排序带来的收益减小。两个后端的结果分别报告，不直接比较其绝对速度。

这些问题针对受控的资源与任务模拟场景；单槽 SJF+aging 本身是通用作业调度方法，实验不证明其为真实 QPU 专有调度方法，也不回答量子门保真度、校准或量子比特拓扑调度问题。

#### 4.1.2 核心创新点

1. 在教学 rCore 中实现从异步提交到中断完成、进程唤醒和结果回收的完整路径，提供可复现的 QPU 异构设备支持原型。
2. 为 QEMU 与 FPGA 建立一致的最小寄存器协议和测试向量，分别验证软件调度逻辑、虚拟 MMIO/IRQ 和实际硬件通信。
3. 将估时误差、aging 阈值和持续短任务到达纳入受控实验，给出性能与公平性的适用条件及反例。

本项目的贡献主要在系统实现和实验分析。SJF、aging 和异步设备驱动均采用已有思路；是否具有超出课程实践的学术新意，还需结合相关工作判断。

#### 4.1.3 对比基线、评测指标及预期提升

对比基线为 FCFS；纯 SJF 用于识别长度排序效果；SJF+aging 为主要研究策略。三者共用驱动、设备协议、队列容量、CPU 调度配置及任务轨迹，只替换设备任务选择规则。原始 rCore 用于回归测试和新增机制开销观察，因其没有本项目 QPU 队列，不能充当直接的 QPU 调度性能基线。

每个被接收任务记录 a（内核接收入队）、d（开始派发）、c（内核处理完成事件）及 u（用户成功获取结果）的时间。设备 BUSY 时间由累计周期计数器的窗口差值获得，并按该后端的设备频率换算。主机侧时间戳均来自同一单调时钟，不将不同钟域原始值直接相减。

| 指标 | 定义与解释 |
| --- | --- |
| 队列等待 W | d−a；报告均值、P95、P99 和最大值 |
| 系统周转 T | c−a；包含派发、设备执行和完成通知开销 |
| 用户可见延迟 | u−a；另含进程再次获得 CPU 的等待 |
| 吞吐量 | 固定测量窗内完成任务数除以窗口时长，同时报告接收与拒绝数 |
| 模拟设备利用率 | 测量窗内 BUSY 时间除以窗口时长，裁剪窗口边界 |
| 公平性与饥饿迹象 | 分长短任务报告最大等待、尾延迟、超阈值比例及截止时仍未完成数 |
| slowdown | T 除以配置的非零服务时长，按任务类型报告分布 |
| 系统开销 | submit 路径、调度选择、ISR 处理时间和 CPU 忙等占用，分别测量 |

中断处理时间以 ISR 入口至出口统计；设备完成到 ISR 入口的通知延迟，需要同钟域计数器或可校准的硬件观测，无法获得时标为未测，不用总周转时间替代。因此，QEMU 宿主机耗时不能代替 FPGA 中断延迟。

预期在部分负载下观察到平均延迟改善，同时量化长任务尾部等待的变化；具体结果由实验确定。单执行槽且服务总量相同时，仅调整顺序通常不会直接提高理想设备吞吐量或利用率，变化也可能来自调度、派发和空闲间隙；需结合 BUSY 记录解释。负结果、无明显差异及额外开销均是有效研究结论。

### 5.2 测试方法

**正确性测试：**

1. 基线回归：原始内核构建启动及基本用户程序可运行，加入驱动后重复回归。
2. 单任务与多进程：检查句柄、状态顺序、结果匹配和所有权；每个已接收任务恰好进入一个完成或失败状态，无静默丢失或重复完成。
3. 并发边界：覆盖完成先于 wait、登记等待时完成、多个等待者、重复/迟到 IRQ、BUSY 重复 START、结果回收重试及资源额度耗尽。
4. 异常与清理：覆盖非法指针、参数上限和溢出、越权句柄、进程退出、执行超时、复位和设备不可恢复错误；检查内存及句柄回收。
5. 后端一致性：使用同一命令序列核对 QEMU 与 RTL 的状态、结果和 ACK 语义；上板通过串口事件记录及可用的片上逻辑分析仪核对总线与 IRQ。
6. 独立调度参考：用离线参考调度器对已入队轨迹计算预期选择次序，对照内核事件日志；不只检查最终任务总数。

**调度性能测试：**

以下数值用于规划实验，不代表实测性能或真实 QPU 参数。参考服务时长记为 s0，先做计时校准，使最短任务能被计时分辨率可靠区分，并在最终配置中明确 s0 的时间单位及其对应的内核 tick 和设备周期数。estimated_ticks 与 actual_ticks 先采用统一的实验时间单位，驱动再按后端频率换算 EXEC_TICKS；换算规则和舍入误差随配置记录。换算后须满足 32 位寄存器的正整数范围，超出范围的任务在接收时拒绝。性能实验的运行超时阈值按允许的最大服务时长加完成通知裕量设置，不从可能低估的 estimated_ticks 推导，避免将估时误差误判为设备故障。

| 负载 | 拟定配置 | 检验目的 |
| --- | --- | --- |
| A 同长度 | 所有服务时长为 s0，分别采用低负载与排队负载 | 观察无长度差异时的策略开销 |
| B 长短混合 | 80% 为 s0，20% 为 20s0；另测 50/50 比例；分别测试全部入队后统一开始派发的批量负载和在线到达负载 | 检查长任务队首阻塞和平均延迟 |
| C 突发 | 1、4、8 个提交进程；突发量为队列容量的 1/2、1、2 倍 | 检查队列上限、背压、吞吐与拒绝 |
| D 饥饿压力 | 先运行占位任务，在其完成前将待测长任务与首批短任务入队，随后持续注入短任务；固定截止后停止新提交并排空 | 检查 aging 的最大等待与未完成任务 |
| E 估时误差 | 准确估时、独立 ±25% 与 ±50% 扰动、长任务系统性低估；最小值截为正数 | 检查 SJF 对估时质量的依赖 |
| F 短任务边界 | 服务时长逐步接近提交及中断开销的量级 | 检查系统开销是否抵消排序收益 |

批量负载的统一派发屏障只用于测试，不属于正式接口语义。饥饿压力测试中的占位任务只用于建立初始队列，其数据单独标记，不计入待测长短任务的延迟统计。

在线负载采用固定种子的指数到达间隔，并按 rho=到达率×平均配置服务时长设置 0.3、0.7、0.95 三档目标负载，实际利用率另测；单独使用 rho 大于 1 的有限窗口观察过载，不将其视为稳定态。各策略回放同一条预先生成、与任务完成时刻无关的到达轨迹，区分计划到达时间与内核实际接收时间；避免只在前一任务完成后再提交下一任务，使测试失去排队竞争。

每个配置拟运行至少 10 个独立种子，同一种子下各策略使用相同的任务轨迹；正式记录前完成固定热身，使用独立的固定测量窗，窗口结束时记录积压并继续排空，追踪测量窗内入队任务的最终周转。为估计尾部分位数，目标为每个配置下的每种策略累计不少于 10000 个完成任务；若硬件耗时无法达到，明确报告实际样本数与尾部统计的局限。

无拒绝的配置作为延迟对比的主要依据。过载时，不同策略可能接收不同的任务子集，因此除拒绝率外，还需按任务类别报告接收数和完成数；不能只凭成功任务的平均延迟判定优劣。

按种子计算策略间配对差值，报告均值、离散程度及基于种子的 95% 置信区间，保留原始记录。轮换策略运行顺序，统一日志粒度，先将事件写入有界内存日志，再在测量结束后导出，避免同步串口输出影响计时；记录日志溢出，发生溢出的运行不用于正式统计。队列满的拒绝请求不混入成功任务平均延迟，同时单独报告拒绝率，防止以丢弃任务制造性能改善。

硬件至少重复单任务、并发、混合长短及 aging 压力四类核心用例；若只完成部分配置，逐项列出验证覆盖范围。QEMU 用于可控语义和大规模轨迹验证，FPGA 用于真实总线与 IRQ 验证，不以模拟器结果宣称实际硬件时序精度。

**阶段安排与风险控制：**

| 阶段 | 工作与验收门槛 |
| --- | --- |
| 第一阶段 | 固定 rCore 基线、启动 QEMU、确认硬件 CPU/总线/IRQ 拓扑；具体日期待填写 |
| 第二阶段 | 完成 QEMU MMIO/IRQ 模型、驱动、异步接口与 FCFS，跑通端到端正确性 |
| 第三阶段 | 实现 SJF，建立参考轨迹与日志，取得可复现的 FCFS/SJF 对比 |
| 第四阶段 | 增加阈值式 aging，开展公平性、估时误差和阈值敏感性实验 |
| 第五阶段 | 完成 RTL 仿真、上板链路及硬件核心负载，整理数据与报告 |

协议确定后，简靖康可推进 FPGA RTL，王子源继续实现内核接口和调度；QEMU 模型先提供最小功能，随后补齐异常与计数器语义。双方以共用测试向量检查接口，避免各模块完成后才发现协议不一致。

若 aging 实现进度受限，可按上述阶段先交付 FCFS/SJF，再交付 aging。最终报告须列出各阶段完成情况，仅有 FCFS 的驱动演示不能支持策略对比结论。若硬件拓扑不满足 MMIO/IRQ，应尽早调整平台并说明影响；若改用 UART 桥接，应另行说明验证范围，不能视为直接 MMIO/IRQ 验证。预算、设备可用日期与各阶段日期待填写。

### 5.3 最终交付

1. rCore 扩展源码：QPU 设备抽象、驱动、系统调用、任务队列、生命周期和中断处理。
2. FCFS、SJF、SJF+aging 实现及策略配置；如有未完成阶段，列明状态和影响。
3. QEMU 虚拟 QPU 设备模型源码、补丁及构建配置。
4. FPGA QPU Emulator HDL、测试平台、仿真波形、约束与工程文件；已上板版本附 bitstream 和生成说明。
5. 用户态单任务与多进程测试程序、压力及故障测试用例。
6. 负载生成器、固定种子和原始轨迹、离线参考调度器、时间戳事件日志及分析脚本。
7. 对比实验报告：假设、控制变量、样本量、指标、配对统计、估时误差与公平性分析，以及负结果和适用边界。
8. README 与复现清单：基线及项目 SHA、工具版本、构建运行步骤、寄存器协议、平台连线、地址与 IRQ 配置、已知限制。
9. 端到端演示及验收记录：异步提交后执行 CPU 工作、等待阻塞、设备中断唤醒、结果回收和策略对比；分别标明 QEMU、RTL 仿真和 FPGA 实测证据。

项目按接口正确性、可核查的执行轨迹和可复现的实验结果验收。性能结论以实测数据为准，上板完成情况单独记录。
